# Границы доверия

```text
┌─────────────────────────────────────────────────────────────────┐
│ Пользователь / Chat UI                                          │
│ Недоверенный язык; возможна prompt injection                    │
└───────────────────────────────┬─────────────────────────────────┘
                                │ только сообщение пользователя
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│ ASP.NET Core Agent Service                                      │
│ Оркестрация LLM, состояние, уточнения, MCP-клиент               │
│ Токен — runtime-контекст, не prompt и не аргумент tool          │
└───────────────────────────────┬─────────────────────────────────┘
                                │ MCP /mcp + делегированная identity
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│ OilCaseX.McpServer                                              │
│ Каталог tools, проверка схем, policy, confirmation               │
│ Типизированный REST adapter, проекция, audit и telemetry         │
└───────────────────────────────┬─────────────────────────────────┘
                                │ HTTPS + Bearer + trace-контекст
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│ OilCaseX REST API                                               │
│ Финальная авторизация, доменная валидация, транзакции            │
└───────────────────────────────┬─────────────────────────────────┘
                                ▼
                     Доменные хранилища OilCaseX
```

## Правила границ

- Результат LLM — недоверенный ввод: он не может расширить реестр tools или выбрать URL.
- MCP policy не зависит от выбора tool моделью.
- OilCaseX API является финальной границей авторизации и бизнес-валидации.
- Учётные данные продуктовой БД никогда не находятся в Agent Service или MCP Server.
- Secrets, JWT и полные чувствительные payloads удаляются из telemetry.
- Содержимое API/RAG — это данные, а не инструкции, способные изменить system policy.
- Write-операция считается завершённой только после подтверждения и аудита ответа API.
